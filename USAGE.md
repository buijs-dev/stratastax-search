# Usage

This document shows how to use `search-core` in an application, end to end: from declaring the
searchable fields of an entity to returning a paginated page from a REST endpoint.
The contract-level behavior (syntax, cursors, errors) is described in the [README](README.md).

The examples use named arguments, except for varargs (`and`, `or`, `inValues`, `after`, ...), infix
operators and Java methods, which do not support them or read better without.

The examples use a `Match` entity throughout:

```kotlin
data class Match(
    val id: UUID,
    val name: String,
    val status: MatchStatus,
    val score: Int,
    val active: Boolean,
    val playedAt: Instant,
)

enum class MatchStatus { PENDING, ACTIVE, COMPLETED, CANCELLED }
```

> In a full Stratastax setup the configuration below is generated by
> [stratastax-codegen](https://github.com/buijs-dev/stratastax-codegen) from the `@SearchFilter`
> and `@SearchSort` annotations of [stratastax-entity](https://github.com/buijs-dev/stratastax-entity),
> and [stratastax-quarkus](https://github.com/buijs-dev/stratastax-quarkus) wires the parser and assembler.
> This document shows the hand-written equivalent, so it is clear what each part does.

## 1. Declare the entity fields

Every searchable field is an `EntityField` (from `stratastax-entity`). It describes the name the
client uses, its type, and whether it may be used in `filter` and/or `sort`.

```kotlin
import dev.buijs.stratastax.entity.core.api.EntityField
import dev.buijs.stratastax.entity.core.api.EntityFieldType

object MatchFields {

    val id =
        EntityField(
            name = "id",
            type = EntityFieldType.UUID,
            sortable = true,
            filterable = true,
        )

    val name =
        EntityField(
            name = "name",
            type = EntityFieldType.STRING,
            sortable = true,
            filterable = true,
        )

    val status =
        EntityField(
            name = "status",
            type = EntityFieldType.ENUM,
            filterable = true,
            enumValues = MatchStatus.entries.map { it.name }.toSet(),
        )

    val score =
        EntityField(
            name = "score",
            type = EntityFieldType.NUMBER,
            sortable = true,
            filterable = true,
        )

    val active = EntityField(name = "active", type = EntityFieldType.BOOLEAN, filterable = true)

    val playedAt =
        EntityField(
            name = "playedAt",
            type = EntityFieldType.DATETIME,
            sortable = true,
            filterable = true,
        )
}
```

Things to keep in mind:

- Field names are camelCase; nested properties are flattened with `"game.title".toSearchFieldName()`
  (gives `gameTitle`).
- An `ENUM` field must list its allowed values in `enumValues`; anything else is rejected, case-sensitively.
- Fields that are neither `sortable` nor `filterable` can be part of the configuration but are
  rejected when a client uses them.

## 2. Create the search configuration

A `SearchConfiguration` bundles the fields with the limits and the default sort of an endpoint.
`StandardSearchConfiguration` is the ready-made implementation.

```kotlin
import dev.buijs.stratastax.entity.core.api.desc
import dev.buijs.stratastax.search.core.spi.StandardSearchConfiguration

val matchSearchConfiguration =
    StandardSearchConfiguration(
        defaultLimit = 20, // used when the request has no limit
        maxLimit = 100, // larger limits are rejected
        defaultSort = listOf(MatchFields.playedAt.desc()), // used when the request has no sort
        tiebreakerField = MatchFields.id, // appended to every sort, makes ordering deterministic
        fields =
            listOf(
                MatchFields.id,
                MatchFields.name,
                MatchFields.status,
                MatchFields.score,
                MatchFields.active,
                MatchFields.playedAt,
            ),
    )
```

The tiebreaker must be unique per row (usually the primary key) and sortable.

### Related fields (field groups)

Fields of a related model are flattened into the configuration and described with a `FieldGroup`.
A group is purely descriptive; the backend decides how to join it.

```kotlin
val gameTitle =
    EntityField(
        name = "game.title".toSearchFieldName(),
        type = EntityFieldType.STRING,
        filterable = true,
    )

val configuration =
    matchSearchConfiguration.copy(
        fields = matchSearchConfiguration.fields + gameTitle,
        groups =
            listOf(
                FieldGroup(
                    name = "game",
                    domainType = GameRef::class,
                    relation = FieldGroupRelation.OneToOne,
                    fieldNames = listOf(gameTitle.name),
                ),
            ),
    )
```

### Search fields by property name

Instead of keeping a separate `object` with field constants, fields can be resolved from the
configuration by property name. Accessing a property that has no matching field throws a
`SearchException`.

```kotlin
import dev.buijs.stratastax.search.core.spi.asFields

object MatchSearchFields {
    private val fields = matchSearchConfiguration.asFields()

    val name by fields
    val status by fields
    val score by fields
    val playedAt by fields
}
```

## 3. Wire the parser and assembler

The `SearchParser` turns an HTTP request into a validated `SearchQuery`. The `CursorPageAssembler`
turns the rows found by your repository into a `CursorPage` with signed cursors. Both need the
same `CursorCodec`. Create them once and share them (e.g. as application-scoped beans).

```kotlin
import dev.buijs.stratastax.search.core.api.CursorPageAssembler
import dev.buijs.stratastax.search.core.api.SearchParser
import dev.buijs.stratastax.search.core.api.standardCursorCodec
import dev.buijs.stratastax.search.core.api.standardFilterParser
import dev.buijs.stratastax.search.core.api.standardSortParser
import dev.buijs.stratastax.search.core.spi.CursorSigningKey
import java.time.Duration

// Keep the key secret and identical on every instance, or cursors from one instance are
// rejected by another.
val signingKey = CursorSigningKey { System.getenv("SEARCH_CURSOR_KEY").toByteArray() }

val cursorCodec = standardCursorCodec(signingKey = signingKey)

val searchParser =
    SearchParser(
        cursorCodec = cursorCodec,
        filterParser = standardFilterParser(),
        sortParser = standardSortParser(),
        cursorExpiry = Duration.ofHours(1), // optional, default 24 hours
    )

val pageAssembler = CursorPageAssembler(cursorCodec = cursorCodec)
```

## 4. Handle a search request

The REST layer maps its query parameters onto a `SearchRequest` and parses it against the
configuration of the endpoint:

```kotlin
import dev.buijs.stratastax.search.core.api.SearchCriteria
import dev.buijs.stratastax.search.core.api.SearchRequest

// GET /v1/matches?limit=10&filter=status==ACTIVE;score=ge=50&sort=playedAt:DESC
fun searchMatches(limit: Int?, filter: String?, sort: String?, cursor: String?): CursorPage<Match> {
    val request =
        SearchRequest(
            limit = limit,
            criteria = SearchCriteria(sort = sort, filter = filter),
            cursor = cursor,
        )

    val query = searchParser.parse(request = request, configuration = matchSearchConfiguration)
    val page = matchRepository.search(query = query)
    return pageAssembler.assemble(search = query, page = page, keyExtractor = matchKeyExtractor)
}
```

The resulting `SearchQuery` contains:

| Property | Content                                                                       |
|:---------|:------------------------------------------------------------------------------|
| `limit`  | The requested limit, or the default limit of the configuration.              |
| `sort`   | The requested sort (or the default sort), always ending with the tiebreaker. |
| `filter` | The parsed filter tree, or `null`.                                            |
| `cursor` | The decoded and verified cursor, or `null` for the first page.                |

`parse` throws a `SearchException` for an invalid limit, sort or filter, and an
`InvalidCursorException` (a subclass) for a malformed, expired or mismatching cursor. Map them to a
`400 Bad Request`, for example:

```kotlin
fun toResponse(e: SearchException): Response =
    when (e) {
        is InvalidCursorException -> badRequest(code = "INVALID_CURSOR", message = e.message)
        else -> badRequest(code = "INVALID_SEARCH", message = e.message)
    }
```

## 5. Execute the query

Executing a `SearchQuery` is backend specific: `search-core` has no database code.
[stratastax-persistence](https://github.com/buijs-dev/stratastax-persistence) implements this for
jOOQ through the `SearchQueryTranslator` SPI. A repository has to:

1. Translate `query.filter` into a `WHERE` clause (walk the `FilterExpression` tree:
   `AndExpression`, `OrExpression`, `ComparisonExpression`, `InExpression`, `LikeExpression`).
2. Translate `query.sort` into an `ORDER BY` clause.
3. When `query.cursor` is present, add a keyset condition on its `values` (one per sort field, in
   sort order). For `CursorDirection.BEFORE`, read in reversed order and reverse the rows back.
4. Fetch `limit + 1` rows, so it knows whether there is more.

```kotlin
import dev.buijs.stratastax.search.core.api.Page

fun search(query: SearchQuery): Page<Match> {
    val rows = fetch(query = query, limit = query.limit + 1) // backend specific
    return Page(items = rows.take(query.limit), hasMore = rows.size > query.limit)
}
```

## 6. Build the page with cursors

The assembler needs to know the sort-key values of a row to put them in a cursor. Provide a
`CursorKeyExtractor` that returns one `CursorElement` per sort field, in `sort.fields` order. The
easiest way is a map from field name to value, converted with `toCursorElement`:

```kotlin
import dev.buijs.stratastax.search.core.spi.CursorElement
import dev.buijs.stratastax.search.core.spi.CursorKeyExtractor
import dev.buijs.stratastax.search.core.spi.filterElementsFor
import dev.buijs.stratastax.search.core.spi.toCursorElement

private val matchCursorValues: Map<String, (Match) -> CursorElement> =
    mapOf(
        "id" to { it.id.toCursorElement("id") },
        "name" to { it.name.toCursorElement("name") },
        "score" to { it.score.toCursorElement("score") },
        "playedAt" to { it.playedAt.toCursorElement("playedAt") },
    )

val matchKeyExtractor =
    CursorKeyExtractor<Match> { item, sort ->
        matchCursorValues.filterElementsFor(item = item, sort = sort)
    }
```

Every sortable field needs an entry. `toCursorElement` supports `String`, `UUID`, enums, `Boolean`,
numbers and the common date/time types out of the box. For other types (e.g. a value class), register
a `CursorValueFactory`:

```kotlin
@JvmInline value class MatchCode(val value: String)

object MatchCodeCursorValueFactory : CursorValueFactory<MatchCode> {
    override val type = MatchCode::class

    override fun convert(value: MatchCode, fieldName: String) = CursorElement.StringValue(value = value.value)
}

val registry =
    CursorValueFactoryRegistry
        .builder()
        .register(factory = StringCursorValueFactory)
        .register(factory = MatchCodeCursorValueFactory)
        .build()

val element = code.toCursorElement(fieldName = "code", registry = registry)
```

The assembled `CursorPage` maps one-to-one onto the response body described in the
[README](README.md#pagination):

```kotlin
val page = pageAssembler.assemble(search = query, page = rows, keyExtractor = matchKeyExtractor)

MatchSearchResponse(
    criteria = request.criteria,
    pagination =
        Pagination(
            limit = query.limit,
            cursor =
                Cursor(
                    previous = page.previousCursor,
                    current = page.currentCursor,
                    next = page.nextCursor,
                ),
        ),
    items = page.items.map { it.toDto() },
)
```

## 7. Build queries in code with the DSL

Outside of HTTP (in services, jobs and tests) a `SearchQuery` can be built with the type-safe DSL
instead of parsing strings.

### Search with a configuration

Passing the configuration applies its default limit and default sort, and appends the tiebreaker,
exactly like `SearchParser` does:

```kotlin
import dev.buijs.stratastax.search.core.api.and
import dev.buijs.stratastax.search.core.api.eq
import dev.buijs.stratastax.search.core.api.ge
import dev.buijs.stratastax.search.core.api.search

val query =
    search(configuration = matchSearchConfiguration) {
        limit = 50
        sort {
            MatchFields.playedAt.desc()
            MatchFields.name.asc()
        }
        filter {
            and(
                MatchFields.status eq MatchStatus.ACTIVE,
                MatchFields.score ge 50,
            )
        }
    }
// sort = playedAt DESC, name ASC, id ASC (tiebreaker)
```

### Search without a configuration

The plain `search { }` has no default sort and no tiebreaker, so a `sort { }` is required:

```kotlin
val query =
    search {
        sort { MatchFields.name.asc() }
        filter { MatchFields.active eq true }
    }
```

### Filter operators

Typed operators take Kotlin values and check them against the field type:

| DSL                                         | RSQL equivalent                   |
|:--------------------------------------------|:----------------------------------|
| `status eq MatchStatus.ACTIVE`              | `status==ACTIVE`                  |
| `status ne "CANCELLED"`                     | `status!=CANCELLED`               |
| `playedAt gt Instant.parse("2026-…Z")`      | `playedAt=gt=2026-…Z`             |
| `score ge 50` / `score lt 18` / `le`        | `score=ge=50` / `score=lt=18`     |
| `status isIn listOf(PENDING, ACTIVE)`       | `status=in=(PENDING,ACTIVE)`      |
| `status notIn listOf(CANCELLED)`            | `status=out=(CANCELLED)`          |
| `playedAt eq null` / `playedAt.isNull()`    | `playedAt==null`                  |
| `playedAt.isNotNull()`                      | `playedAt!=null`                  |
| `name.like(pattern = "Alex%")`              | `name=like="Alex%"`               |
| `name.ilike(pattern = "%alex%")`            | `name=ilike="%alex%"`             |
| `name.containsIgnoreCase(value = "100%")`   | `name=ilike="%100\\%%"` (escaped) |

Values are typed per field: `NUMBER` accepts `Int`, `Long`, `Short`, `Float`, `Double` and
`BigDecimal`; `DATE`/`DATETIME` accept `Instant` and `OffsetDateTime`; `ENUM` accepts an enum
constant or its name; `JSON` accepts the raw JSON text as `String`. A mismatch, or an operator that
is not allowed for the field type (e.g. `like` on a number), throws a `SearchException` right away.

When the values come in as text (e.g. from configuration or a CSV), use the string variants. They
parse the value exactly like the RSQL parser does:

```kotlin
MatchFields.score.greaterThanOrEqual(value = "50")
MatchFields.playedAt.lessThan(value = "2026-08-04T10:00:00Z")
MatchFields.status.inValues("PENDING", "ACTIVE")
MatchFields.status.notInValues("CANCELLED")
MatchFields.name.equalsValue(value = "null") // the null keyword: same as isNull()
```

### Combining conditions

`and(...)` and `or(...)` nest freely; with a single argument they return that argument unchanged.

```kotlin
// playedAt=ge=2026-01-01T00:00:00Z;(status==COMPLETED,score=gt=100)
filter {
    and(
        MatchFields.playedAt ge Instant.parse("2026-01-01T00:00:00Z"),
        or(
            MatchFields.status eq MatchStatus.COMPLETED,
            MatchFields.score gt 100,
        ),
    )
}
```

### Resuming from a position

`after(...)` and `before(...)` take the sort-key values of a row, one per sort field (including the
tiebreaker). The cursor hash is computed from the query's own sort and filter, so the result can be
passed straight to a repository or the assembler:

```kotlin
val nextPage =
    search(configuration = matchSearchConfiguration) {
        sort { MatchFields.score.desc() }
        after(
            CursorElement.NumberValue.of(value = 75),
            CursorElement.StringValue(value = lastId.toString()),
        )
    }
```

An already decoded `CursorState` can be passed with `after(cursor = cursorState)`.

## 8. Testing an endpoint

A typical e2e test walks through all pages and checks that no row is skipped or duplicated:

```kotlin
import kotlin.test.assertEquals

@Test
fun `pages through all active matches`() {
    val seen = mutableListOf<UUID>()
    var cursor: String? = null

    do {
        val page = searchMatches(limit = 10, filter = "status==ACTIVE", sort = "score:DESC", cursor = cursor)
        seen += page.items.map { it.id }
        cursor = page.nextCursor
    } while (cursor != null)

    assertEquals(expected = seen.distinct(), actual = seen)
    assertEquals(expected = activeMatchCount, actual = seen.size)
}

@Test
fun `rejects a cursor with changed criteria`() {
    val first = searchMatches(limit = 10, filter = "status==ACTIVE", sort = null, cursor = null)

    assertThrows<InvalidCursorException> {
        searchMatches(limit = 10, filter = "status==PENDING", sort = null, cursor = first.nextCursor)
    }
}
```
